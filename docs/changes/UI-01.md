# UI-01 — Combat HUD

Status: integrated

## What changed

- Added a Wasteland 2 combat display with four clickable weapon slots, cooldown rings, keyboard and gamepad hints, and a ready/charging state.
- Added a player armor bar and one armor marker for every active opponent. Visible opponent markers use the read-only screen projection added by VIS-02 (`projectOpponents()`); offscreen opponents get a direction and distance label.
- Added a short hit marker for strikes on opponents and an arrow based on the actual player damage zone for incoming hits.
- Kept the existing weapon bar and crash HUD for ordinary and flag-off Mad Max races. The new HUD only reads simulation state and events. It does not change race rules or saves.
- Text nodes and accessible labels are updated only when their displayed values change. The browser check observed zero text mutations on a repeated identical HUD frame.

## Review notes

- The browser scenario's first attempt called the projection method on the debug object. VIS-02 exposes it on the renderer handle. The scenario now checks the HUD consumer output; no production assertion was weakened.
- Opponent labels stay within the viewport near the camera edge, so a label can shift slightly inward from its projected car. The directional fallback remains available when the car is behind or outside the view.
