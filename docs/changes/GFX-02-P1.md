# GFX-02-P1: first-person Rook hand proof

status: design proposed; no implementation

## Baseline and decision

The merged round-three first-person set remains the runtime baseline. At lane base `86369b8`, `hands/rook.glb` has SHA-256 `34de29dd6a2fb446cd9b8ac2f48ba5ffa3a0171ce40a331eb427763cd702c02c`; `tools/blender/first-person-gear.py` has SHA-256 `ce44f754c56962bb41dc75e9c79922f459bffe73a382bb41b408b495c57f7a3c`. The other seven hand assets, shared tools, selector and renderer remain unchanged in this proof. Round three scored 3/3/3/3; the scoped frame result was 18.1 ms hidden and 18.2 ms visible at p95 with 120 samples, 6,932 triangles and three draws at the largest combination. It did not measure texture memory or full presentation CPU.

The final Rook body P2 visual verdict was likeness three without runtime promotion; its merge gate is still pending. Its connected surfaces, measured contours, padded explicit UVs and source verification are useful construction techniques, but they do not certify a winning whole-body method. Prove the hand independently after that gate before considering the other crews. Reversal is to stop selecting the opt-in candidate and retain the above committed runtime GLB; no saved data, gameplay, tool asset or old review sheet changes.

## Construction and authored source

Add the small committed `tools/blender/first-person-p1-source.json` for measured Rook hand contours, digit lengths/widths, knuckle and grip landmarks, cuff hem, and painted material chart allocation. It is an authored input with source-reference crop and hash, not a generated mesh dump. Keep the geometry/rig/export algorithm in `first-person-gear.py`. This separates anatomy decisions from reusable meshing code and permits red tests against actual declared landmarks. A new dependency or implicit discovery of ignored files is unnecessary.

Use the generator's existing camera-local authoring metre frame: X right, Y up, and forward along negative Z. The generator's `bv` converts authoring (x,y,z) to Blender (x,-z,y) once. The fixed right RPG grip is (0.14, -0.24, -0.55) m; the left support grip is the same point shifted -0.34 m in Z; the wrench grip is (0.21, -0.24, -0.58) m. These are existing tool/socket coordinates, not inferred reference anatomy. The Rook body/arms crop [0,40,510,675] in `public/assets/reference/wasteland-crew-1.png` guides sleeve and glove appearance; it is not a detailed RPG-arm anatomy view. Hidden palm depth, web thickness and fingertip underside are necessarily inferred for grip and motion and must be labelled as such in the JSON and proof manifest. The unchanged actual RPG and wrench meshes are the contact oracles.

The initial anatomy envelope, to refine only through an independently reviewed reference trace, is palm breadth 0.065–0.115 m, wrist-to-knuckle length 0.065–0.125 m, four distinct finger lengths 0.045–0.105 m, and thumb root-to-pad 0.035–0.075 m. The thumb web at its narrowest useful cross-section must be 0.012–0.040 m wide, with visible concavity rather than a separate club. These bounds keep the existing approximately 0.11 m wide palm and posed grip plausible; they are *inferred hand-space construction limits*, not measured pixel claims from the small reference. Source JSON should record the reference/inferred provenance per landmark, then the exported mesh should be checked against the chosen bounds.

The JSON contract is `{schemaVersion:1,units:"metres",frame:"camera-local-x-right-y-up-negative-z-forward",reference:{path,sha256,crop},hands:{R:{landmarks:{wrist,palm,knuckles:{index,middle,ring,pinky},fingertips:{index,middle,ring,pinky},thumbRoot,thumbWeb,thumbTip},provenance:{...}},L:{...}},atlas:{size:1024,paddingPixels:8,charts:{skin:{rect},leather:{rect},cloth:{rect}}}}`. Each landmark is a three-number authoring-frame point; provenance labels each landmark `reference-visible` or `inferred-grip`. Chart rectangles are integer PNG pixel bounds, disjoint after padding. The source must contain actual chosen numbers before export, not defaults silently invented by the builder. On export, the single skinned hand mesh carries named vertex-group or equivalent GLB extras for `R/L:palm`, `thumbWeb`, `thumbTip`, four distal digit pads, and cuff seam. The tags identify measurement regions only; acceptance measures their actual positions, connectivity, normals and UVs instead of trusting tags alone.

Build one connected deforming hand surface per side from wrist through shaped metacarpals, palm, thenar web, thumb and four separated fingers. Branches must share welded surface topology with the palm rather than merely occupy the same skinned object. Weld vertices within 0.0001 m (0.1 mm), then prove an edge-connected hand component; a pinched one-edge bridge does not count as a useful palm/web cross-section. Use staggered digit lengths, width taper, natural knuckle bulges and distinct curl arcs around the tool handle. The thumb web should have a broad concave bridge and a smooth root transition. Avoid palm slabs, separate pad shells and identical finger tubes. Retain current wrist/finger bone names, skin weights that sum to one, `rpg-mount` and `wrench-mount`, and all eight clip names/durations so the current renderer can load the proof without a code change.

Terminate exposed fingertips with rounded multi-ring pads: at least two tapering rings over the last 0.006–0.015 m, a positive-radius end, outward cap normals and no flipped hard edge at the side-to-pad junction. Their terminal faces must sample the skin chart, never the leather chart that closes the current skin loft. Place the glove-to-skin boundary on the intended finger joints with a padded UV seam; require each side to sample its declared material, with at least eight texels of safe padding at 1024 resolution and no tip UV collapsed to a point. Keep a single material and existing 1024 color/surface/normal set for Rook. Start with a deterministic procedural atlas using explicit padded skin, leather and cloth charts plus painted broad wear/seam masks; compare actual in-game pixels to the approved reference. If it stays generic, propose a separately verified reference-derived paint source with its hash and protected charts before using it. Do not imply that unspecified detail is already authored. Build an asymmetric tailored sleeve shell with an open fitted cuff, hem thickness, seam path and worn edge, separate from the continuous hand. It may overlap the wrist but must not make a fake closed skin cap. Use explicit cloth UV strips aligned to the forearm rather than repeated generic sine-fold rings. Preserve texture padding and protected existing tool charts.

## Candidate isolation and review

Proposed CLI: `--p1-rook --output-dir <ignored path under art-build/first-person-p1>`, with `--paths-only` validating the destination before importing Blender or writing files. The default generator behavior and production output paths remain unchanged. The opt-in export writes only Rook's candidate GLB, its rebuilt blend/textures, and manifest to the ignored destination; it must not overwrite `public/assets/models/wasteland/first-person/hands/rook.glb`. The manifest records source JSON/reference hashes, camera/near-plane, material maps, bounds, topology metrics, triangle/draw counts, capture paths and output SHA. No candidate binary is committed before a reviewed promotion.

For independent path tests, `--paths-only` prints JSON with `mode:"p1-rook"`, resolved `outputDir`, `sourceJson`, `candidateGlb`, `candidateBlend`, `textures:{color,surface,normal}`, and `manifest` paths. The candidate names are `hands/rook.glb`, `hands/rook.blend`, `hands/rook-{color,surface,normal}.png`, and `manifest.json` under that output directory. No directory may be created during the path-only call. The built manifest uses `schemaVersion:1`, `mode:"p1-rook"`, `source:{path,sha256,referencePath,referenceSha256}`, `asset:{path,sha256,triangles,draws,textureBytes}`, `regions` with each named region's bounds and actual connected-component ID, `charts` with the pixel rectangles and padding, `clips` with names/durations, `sockets` with positions, and `captures` with path/hash/pose. The build should fail on a public or outside output path before writing, and tests should compare production GLB SHA before and after the isolated build.

Use a private memory-only browser origin for same-origin fetch substitution of only the Rook hands URL. The candidate must pass the production loader, skin, sockets and clips; all other files load from the unchanged bundle. A separate immutable `docs/board/looks/first-person-p1/` sheet family compares native reference, Blender, game High and Performance at matched idle, aim, fire/recoil, reload and repair views. Show a short ordered motion/contact sequence across reload insertion, recoil recovery and repair, including first/last action boundary. Measure grip gaps, tool penetration, near-plane clipping (0.15 m), HUD clearance and full car/menu/other-camera exclusion at the existing 72-degree on-foot FOV. Real input proves exit, successful shot, reload, repair and re-entry; labelled pose snapshots supplement it. Do not infer continuous contact from a single pose. The existing 18.1/18.2 ms result is a limited 120-frame observation. Candidate frame acceptance requires a quiet, same-scene A1/B/A2 comparison of complete production renders in both qualities with ordered CPU and RAF samples, means and p95 against both baselines; do not infer a GPU-time result.

Contact applies to named phases, not every fingertip. In idle, aim, fire and recoil recovery, the right palm/index/thumb grip region must remain within 0.015 m of the RPG handle, while the left support palm remains within 0.020 m of its support grip. During reload progress 0.18–0.76 the left hand deliberately releases that support, reaches the rocket and guides it; require its thumb/index grip region within 0.020 m of the rocket at the guide/insertion samples, then support-handle contact again by progress 0.90–1.00. No left-handle contact assertion is valid during the released interval. For wrench idle and repair, the right palm/thumb grip region stays within 0.015 m of the wrench handle while the tool strokes; the left hand is free and has no tool-contact requirement. These are candidate proof tolerances in tool-local metres, to be evaluated on skinned vertices and the corresponding unchanged tool meshes across ordered phase samples. Allow fingers not used for the pinch to curl freely, but reject visible hand/tool penetration beyond 0.005 m at contact zones.

## Independent red tests before source edits

Crew owns the acceptance tests. Exported GLB tests should inspect actual connected components and manifold branching across palm/thumb/five digits, avoiding an object-name-only pass; meaningful web cross-section and fingertip curvature; outward pad normals and skin-chart UV/pixel sampling; padded material islands and sleeve chart orientation; unchanged wrist/finger bones, skin normalization, sockets, clip names, animation duration, and last-rocket behavior. Preserve the existing 8,000 visible-triangle/three-draw cap with selected tool, 1024 maps, and all default eight-crew tests. Candidate path tests must reject public/outside targets before writes and prove production hashes unchanged. Browser acceptance uses both qualities and memory-only storage. A frame check must compare candidate to baseline in the same real scene and report texture memory as well as draw/triangle counts. A topology or test pass is not a likeness score: independent visual review needs at least four on the Rook hand proof before conversion or runtime replacement.

No `src/first-person-gear.js` change is authorized. If motion review proves the current selector/renderer causes contact loss independently of the GLB clips, record a reproducer and request a named card hook before editing that source. The body P2 merge and Director design approval precede generator implementation.
