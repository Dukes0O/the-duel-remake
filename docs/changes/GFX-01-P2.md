# Rook likeness: authoring contract before code

## Starting evidence and design choice

The round-10 Rook trial scored likeness 2 and was rejected. Its generator used rings, patches, a voxel union, subdivision and automated folds. Connected topology, padded UVs and a triangle budget passed, but the head stayed small above a long exposed neck, the vest looked like inflated columns, the rear pack floated, the trousers and boots were simple, and the face was weak in game. The reviewed round-3 runtime Rook scores 3/3/3/4/4 for likeness/readability/grounding/scene/cost. Its GLB stays byte-identical during this trial. The seven other crew GLBs and the current `tools/blender/crew-fighters.py` also stay unchanged.

Use a **committed, explicitly shaped mesh input**. A Blender artist may edit an ignored working `.blend`, but that file is not the source of record. Export its named control meshes, vertex positions, face indices, UVs, garment roles and bone weights into `tools/blender/rook-p2-source.json`, then rebuild the ignored Blender scene and candidate GLB from that JSON on a clean checkout. The rebuild script must not synthesize Rook's proportions from the old procedural rings or copy the rejected trial mesh. Scripted subdivision and export are allowed after the authored control geometry has fixed the silhouette. Paint uses authored garment regions and local wear, not full-view photo projection.

The reference is `public/assets/reference/wasteland-crew-1.png`, with Rook in the first front, side and back triplet. Before rigging or texture work, trace a small reviewed landmark input in `tools/blender/rook-p2-landmarks.json`: crown, hair width, jaw/chin, neck base, scarf hem, shoulder tips, elbow/wrist, vest opening and hem, large pocket base, belt, crotch, knees, boot shaft/toe/heel, and pack/strap anchors. Store each point in image-pixel coordinates for its view, plus the reference image SHA-256 and the calibration from floor to crown (the approved sheet has Rook floor near y650 and crown near y62; the rebuild must record exact chosen pixels). Render the neutral control mesh at matching full-size front/profile/back views and overlay it on the approved reference and round-3 baseline. A separate reviewer must accept the silhouette before the candidate stage may attach weights or bake paint. Do not infer likeness from vertex count, UV occupancy or a passing rig test.

The authored geometry has an integrated head/jaw/neck body core; separate, thin jacket, open vest panels and pockets, scarf wrapped under the chin, loose cargo trousers, tall narrower boot shafts with a separate toe and sole, and a curved pack with shoulder and belt contact. The sculpted surface must carry these features in front and side views. The pack must not be a flat board behind the torso. Each garment's near and far mesh has stable names so tests can measure its silhouette and contact. The current 1.83 m height, glTF axis convention, existing skeleton and twelve clip names remain the runtime contract.

## Clean-build input and output API

The first implementation slice ends at the **neutral silhouette**. It does not import the runtime rig, paint an atlas, export a candidate GLB or change any runtime file. Those steps need a reviewed neutral silhouette and a second red-test contract.

- **Committed source schema:** `tools/blender/rook-p2-source.json` has `{version:1, units:'metres', coordinates:'blender-z-up', height:1.83, meshes:[...]}`. Every mesh has `{name, role, lod:'near'|'far', vertices:[[x,y,z],...], faces:[[vertexIndex,...],...]}`. The required near roles are `body-core`, `jacket`, `vest-left`, `vest-right`, `scarf`, `trousers`, `boots` and `pack`. Names are stable; faces have valid indices and consistent winding. The body core connects the head and neck through shared mesh vertices, with no detached head or neck shell. Near control triangles total at most 8,000; far control triangles total at most 2,000. These are first-slice ceilings; actual subdivided and exported triangle budgets are checked in the later candidate slice. Later candidate fields may add UVs, material regions and bone weights without changing this neutral geometry. The JSON contains no binary images or copied reference pixels. An ignored artist `.blend` may be serialized into this committed JSON, but the clean rebuild reads only JSON.
- **Committed landmark schema:** `tools/blender/rook-p2-landmarks.json` has `{version:1, reference:{path,sha256,width,height}, height:1.83, views:{front:{crop:[x0,y0,x1,y1],crown,floor,points:{...}},side:{...},back:{...}}}`. Each view has observed image-pixel points for `crown`, `chin`, `neck`, `shoulder`, `elbow`, `wrist`, `scarf`, `vest`, `belt`, `crotch`, `knee`, `boot` and `pack`. A point can be a named pair or more precise left/right subpoints where the view supports it. Coordinates must lie in the stated crop and reflect the actual Rook reference; filling keys with arbitrary points fails the visual review. The first Rook triplet is about x112/287/441 for front/side/back, with crown near y62 and floor near y650 on the approved 2067×761 sheet; the committed data records inspected exact positions. The reference SHA-256 is verified before rendering. Landmarks guide comparison; they do not automatically score likeness.
- **Neutral build command:** `blender -b --python tools/blender/rook-p2.py -- --root REPO --stage neutral --source tools/blender/rook-p2-source.json --landmarks tools/blender/rook-p2-landmarks.json --output-dir art-build/crew/rook-p2`. `--output-dir` defaults to `art-build/crew/rook-p2`. The script resolves it against `--root` and allows outputs only inside that lane's ignored `art-build/` or `.evidence/` trees. It rejects `..` traversal, absolute paths outside those trees, and any route to `public/`, `src/`, reference files or the live checkout before making a directory. The neutral stage rebuilds an ignored `.blend`, produces full-size front/profile/back clay renders and a manifest, and produces **no GLB or textures**.
- **Read-only path query:** `--paths-only` validates the same resolved paths and prints one JSON object `{blend:[...],glb:[],textures:[],evidence:[frontRender,sideRender,backRender,manifest]}` before importing `bpy` or writing any file. This permits the safe-path tests to run without Blender. It must not create an output directory.
- **Neutral manifest:** records the source, landmark/reference and exporter hashes; Blender version; output hashes; coordinate system and height; per-level control-mesh triangle totals; exact camera/crop calibration; and render paths. The clean checkout must reproduce the same structural data and matched silhouettes. Candidate rig, UV, atlas, clips and GLB manifest fields are specified and tested only after neutral silhouette approval.
- **Later candidate stage:** after the silhouette gate, extend the same script with `--stage candidate`. It may import the existing reviewed Rook rig and clips from `public/assets/models/wasteland/crew/rook.glb`, bind authored near/far meshes and weights, bake the one-material 1024-square color/surface atlas set, and export `rook-p2.glb` only under ignored `art-build/` or `.evidence/`. It never modifies a production GLB. The later tests check actual exported triangle, UV, material and clip contracts.
- **Review loading:** `createRiggedFighterFigures({loadAsset})` in `src/rigged-fighter.js` already accepts `(crewId) => Promise<{scene, animations}>`. Structural tests can inject the candidate through that contract. A private browser candidate hook may copy `rook-p2.glb` into the ignored QA bundle and supply it to Rook only; the normal loader path remains `/assets/models/wasteland/crew/rook.glb`. The exact private hook is a later, separately owned slice before game capture.

The ignored `art-build/` and `.evidence/` directories hold intermediate `.blend`, later candidate GLB, atlases and raw captures. Only the script, JSON inputs, tests, compact review sheet and written verdict enter Git. This follows SPEC 0.7 and allows a clean checkout to reconstruct the candidate without a stored `.blend`.
